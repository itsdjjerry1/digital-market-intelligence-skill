# Contributing

Contributions are welcome. Please keep changes evidence-first and provider-neutral where practical.

## Before submitting

- Do not introduce fabricated example metrics without labeling them as fictional.
- Make provider-specific requirements and limitations explicit.
- Keep the skill's core instruction file named `SKILL.md`.
- Add sources and explain assumptions for material factual changes.
- Test workflows against cases where data is incomplete or unavailable.

## Pull requests

Describe the problem, the proposed change, and any limitations or trade-offs. Small, focused changes are easier to review.
